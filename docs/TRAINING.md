# Тренировочный контур Sam

Тренировочный контур развёрнут 24 сентября 2026 года. Проверки, резервная копия
и версия production зафиксированы в `RELEASE-2026-09-24.md`.

## Доступ и приватность

У каждого спортсмена отдельный профиль, планы, логи и личный чат. Новый
пользователь попадает в систему только по одноразовому приглашению:

1. Настроенный числовой Telegram ID Alexey в личном чате вызывает `/invite`.
2. Он передаёт созданную строку `/start <токен>` новому человеку.
3. Новый человек отправляет её **в личный чат с ботом**. У приглашения есть
   срок действия; повторное использование не создаёт второй профиль.

Приглашённый получает пустой приватный профиль: чужие цели, история и
снаряжение не копируются. `/whoami` остаётся доступной для проверки Telegram
ID.

Ответы в настроенной группе включаются отдельно: `/sharing on` или `/sharing off`.
В группе Sam отвечает только о том, кто задаёт вопрос: чужие тренировки, сравнения
с друзьями и записи другого человека недоступны. Чужая история не загружается в
контекст модели. Даже администратор не может попросить раскрыть чужую историю.
Ответ о твоих тренировках в группе видят её участники; для приватного обсуждения
пиши лично. Личные заметки, причины и источники фото в групповой контекст не попадают.
После отзыва согласия уже поставленные в очередь групповые ответы не доставляются.

## Тематика и ограничение расходов

Sam занимается только скалолазанием и тренировками, включая бег, силовые,
восстановление и связанное с подготовкой питание. Оффтоп и смешанные запросы
отклоняются, а не передаются полноценному коучу. Очевидный оффтоп не вызывает ИИ;
для остальных сообщений используется ограниченная проверка темы без чужой памяти.
Если проверка недоступна или не уверена, Sam просит уточнение, а не запускает коуча.

Настраиваемые лимиты по умолчанию: 30 оплачиваемых запросов в час и 120 за скользящие
24 часа на человека, 300 за 24 часа на всех. Изменение сообщения расходует новый
допуск; повторная доставка той же редакции — нет. Это лимиты обработок, не гарантия
конкретного долларового бюджета: внутри одной обработки возможны несколько API-вызовов.
Основные выходы модели также ограничены числом токенов.

Текст — до 6000 символов, голосовое — до 3 минут, видео — до 5 минут. Для обычного
видео нужен запрос о своей технике до его разбора. Голосовые и кружочки сначала
расшифровываются: отсечь их оффтоп без затрат на распознавание невозможно. Длительность
и оставшийся лимит проверяются до платной обработки. Режим фото-каталога тоже
расходует общий допуск; OCR не делает посторонние картинки тренировочным материалом.
Лимиты задаются `POLICY_*` в окружении, сохраняются в БД и рассчитаны на один worker.

## Первичная настройка и команды

В личном чате начните с:

```
/setup Хочу увереннее лазить V5; могу вт/чт/сб вечером; есть турник и резинки.
```

Sam сохраняет только явно названные цели, доступность и снаряжение с привязкой
к сообщению. Если данных нет, их не заменяют догадками.

Основные личные команды:

| Команда | Действие |
| --- | --- |
| `/today` | сегодняшняя активная сессия или запрос безопасного черновика |
| `/week`, `/program` | текущая неделя или программа |
| `/session ID` | конкретная сессия |
| `/log ID` | открыть короткий контекст фактического лога |
| `/export ID` | прислать тот же план в UTF-8 Markdown |
| `/morning HH:MM` / `/morning off` | добровольный утренний план или выключение |
| `/timezone IANA` | часовой пояс, например `America/Toronto` |
| `/sharing on|off` | согласие на настроенный общий чат |
| `/catalog on|off` / `/catalog status` | личная очередь фото-каталога |
| `/skip ID` | явно отметить сессию пропущенной без создания тренировки |

Кнопки сессии открывают те же безопасные маршруты: посмотреть, логировать,
экспортировать, запросить изменение/сокращение/замену/перенос или пропустить.
Изменение не происходит только от нажатия: Sam сначала просит точные новые
числа или дату. Кнопка всегда исполняется как аутентифицированная долговечная
команда владельца указанного ID; текст или имя в интерфейсе не являются
авторизацией.

Программа, неделя и сессия имеют свои версии и ID. Новая валидная версия
заменяет только релевантную область, а не всю историю. Это не обещает, что
каждый разговор автоматически создаст полную программу: неподтверждённые или
неподходящие блоки остаются черновиком/уточнением.

## Фактические тренировки

План — это назначение, а не выполненная работа. После `/log ID` Sam показывает
конкретные плановые числа и предлагает:

- написать фактический результат простой фразой или голосом;
- либо нажать «Подтвердить ровно эти значения».

Только эта отдельная аутентифицированная кнопка может перенести показанные
точные параметры в фактический лог. «Готово», «сделал» или молчание не
заполняют веса, повторы, попытки, дистанцию или отсутствие боли. Если числа
неоднозначны, нужно написать факт; если такой лог уже записан, Sam просит
поправку вместо дублирования. `/skip ID` оставляет аудит пропуска, но не
создаёт Workout и не имитирует результат.

## Фото-каталог

Исходный набор содержит 70 структурированных карточек, из них 18 имеют статус
`ready`. Остальные сохраняются как `draft` / `needs_review`: полнота распознавания
не равна разрешению автоматически назначать нагрузку. Исходные категории,
оборудование, шаги, отдых, база процентов и ограничения хранятся отдельно.

Для `1 On 1 Off`, `1 On 2 Off` и `Continuity 5x3` поддерживается ограниченная
адаптация Sam: уменьшение целого числа повторов/сетов без изменения интенсивности
и отдыха. Нужна причина изменения. Это правило Sam, а не утверждение исходного
приложения; оригинал и персональная версия сохраняются раздельно. Расчётное время
работы/отдыха не включает переходы и отдельную разминку.

Включите `/catalog on` в личном чате и пришлите фото. Оно сначала сохраняется
как приватный `CatalogSource`; затем OCR извлекает только видимый материал
протокола (название, категорию, строки и предупреждения). При сбое источник
остаётся полученным для повторной обработки.

Фото не является тренировкой, не попадает в обычное извлечение упражнений и не
публикует протокол. OCR — стадия очереди на проверку, а не автоматическая
публикация или рекомендация. Очередь проверяется через `/catalog status`.

Исторический приватный пакет восстанавливается отдельной операторской командой,
по умолчанию только в режиме просмотра:

```powershell
python -m app.catalog_import --date 2026-09-24
python -m app.catalog_import --date 2026-09-24 --apply
python -m app.catalog_import --date 2026-09-24 --reconcile
python -m app.catalog_import --date 2026-09-24 --reconcile --apply
```

Первая команда показывает точное число фото, альбомов и прежних ошибок. `--apply`
идемпотентно создаёт приватные источники и возвращает в очередь только прежние
`unsupported_media`; сообщения в Telegram и тренировки не создаются. После OCR
reconcile автоматически связывает только точное однозначное совпадение названия.
Нечёткие совпадения, новые и нечитабельные экраны остаются на ручную проверку.

## Утренние планы и доставка

Напоминание включается только `/morning HH:MM` и использует `/timezone IANA`.
Оно создаёт долговечный элемент доставки для сегодняшней активной сессии; при
рестарте действует ограниченное локальное окно догоняющей отправки, а не
рассылка старых дней. Перед отправкой повторно проверяются opt-in, чат,
локальная дата и актуальность плана. Дедупликация снижает повторы, но Telegram
не даёт здесь обещания exactly-once доставки.

## Локальная проверка и миграция

Запускайте тесты из рабочего каталога:

```powershell
.venv/Scripts/python.exe -m pytest -q
.venv/Scripts/python.exe -m pytest tests/test_training.py tests/test_training_telegram.py tests/test_training_review.py -q
```

Миграция `20260924_0004_training_system` аддитивно добавляет поля планов,
`plan_id` тренировок, delivery payload и новые таблицы доступа/каталога. Перед
её применением нужен проверенный backup и репетиция restore на отдельной
Postgres-копии, включая проверку upgrade/downgrade-процедуры. Для релиза
24 сентября эта проверка выполнена; владелец разрешил деплой. Для следующих
изменений схемы проверку нужно повторять перед обновлением production.

Downgrade удаляет новые таблицы и их данные: это не безопасная отмена новых
тренировочных записей. Для отката после реального использования нужен проверенный
план восстановления, а не слепой запуск downgrade.
